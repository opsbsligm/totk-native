# Steam Deck 确认与取消

Linux 上固定的 TOTK 1.4.3 在标题、背包、地图、系统对话框、商店等已识别的交互菜单中使用物理 **A（南）确认、B（东）取消**。游戏世界的互动、冲刺、战斗，以及快捷武器/素材栏保持原来的按键定义；键盘绑定不变。按住 A/B 跨越菜单边界时，先等释放再接收新操作，避免退出菜单后误触世界操作。

只读识别不执行 guest 方法、不修改 guest 对象：从同版本 ScreenMgr 数组读取已加载的屏幕，检查对象属于该管理器，类型必须命中 22 类明确交互屏幕，并使用游戏自己的打开状态条件。世界 HUD、拾取提示、快捷武器栏不在名单中。模块仍由现有启动器做完整指纹校验，读取失败或类型未知时保留原玩法路径。

`TOTK_MENU_CONFIRM=0` 可显式恢复原始菜单输入。原有游戏 A/B 确认/取消提示随新菜单输入自然对应物理 Deck A/B；游戏玩法的键位定义不做全局交换。帮助图中的原创 Deck 机身采用正确的物理 ABXY 方位，保留玩法说明的原锚点。

静态布局依据在 [版本证据](menu-confirm-static-evidence.txt)。合成内存回归覆盖菜单与世界区分、损坏指针、容量边界、父管理器、可见状态、关闭优先级、类型指纹和跨菜单按住释放。完整游戏操作由用户验收，`hardware_validated=false`，不能把这些软件检查等同于游戏流程验收。
