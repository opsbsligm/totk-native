# Steam Deck 确认与取消

Linux 上固定的 TOTK 1.4.3 在标题、背包、地图、系统对话框、商店等已识别的交互菜单中使用物理 **A（南）确认、B（东）取消**。游戏世界的互动、冲刺、战斗，以及快捷武器/素材栏保持原来的按键定义；键盘绑定不变。按住 A/B 跨越菜单边界时，先等释放再接收新操作，避免退出菜单后误触世界操作。

只读识别不执行 guest 方法、不修改 guest 对象：从同版本 ScreenMgr 数组读取已加载的屏幕，检查对象属于该管理器，类型必须命中 20 类明确交互屏幕，并使用游戏自己的打开状态条件。元数据表保留的 `UICtrlGuideScreen` 是世界底部常驻的移动/操作说明/视角提示，`UIMapScreen` 还负责世界中的常驻小地图；两者必须排除，它们的打开状态不能用于交换世界按键。展开的大地图由实际接管输入的 `UIAppMenuOverlayScreen` 判定，系统控制器帮助页由真正的菜单对象判定。世界 HUD、拾取提示、快捷武器栏不在交互名单中。模块仍由现有启动器做完整指纹校验，读取失败或类型未知时保留原玩法路径。

2026-11-08 的隔离存档实机诊断发现：格鲁德小镇中 `UIMapScreen` 已处于打开状态，物理 A 触发购买、物理 B 没有触发购买；展开地图后 `UIAppMenuOverlayScreen` 才打开，物理 B 能关闭地图。这是本次排除常驻地图对象的依据。该观察器只旁观运行时已有的内存复制，不额外读写游戏内存；修复仍须在新候选包中回归，不能把旧包诊断当作新包验收。

`TOTK_MENU_CONFIRM=0` 可显式恢复原始菜单输入。原有游戏 A/B 确认/取消提示随新菜单输入自然对应物理 Deck A/B；游戏玩法的键位定义不做全局交换。帮助图中的原创 Deck 机身采用正确的物理 ABXY 方位，保留玩法说明的原锚点。

静态布局依据在 [版本证据](menu-confirm-static-evidence.txt)。合成内存回归覆盖菜单与世界区分、损坏指针、容量边界、父管理器、可见状态、关闭优先级、类型指纹和跨菜单按住释放。完整游戏操作由用户验收，`hardware_validated=false`，不能把这些软件检查等同于游戏流程验收。
